# よくある質問

**これはファインチューニングですか？**
いいえ。モデル重み上の optimizer も訓練データもありません。編集は 1 回適用される閉形式または低ランク delta です。唯一の勾配は ROME 求解時の単一 value ベクトル上にあります。

**GPT-2 以外のモデルで動きますか？**
ランタイムは Llama/Qwen/Mistral/Gemma（`model.layers`）、GPT-2/GPT-J（`transformer.h`）、GPT-NeoX（`gpt_neox.layers`）、OPT、MPT の層を発見します。両方の重み方向を扱います。実チェックポイントは GPT-2 124M、Qwen2.5 0.5B / 1.5B / 3B / 7B、Llama-3.1-8B をカバーし、各段で同じベンチマークパネルを使います。

**なぜ LoRA を使わないのですか？**
同じ層・同じステップ数で実測：rank-8 adapter は rewrite 1.000 / rephrase 1.000 に達しますが、44% のパープレキシティと 25 点の MMLU を犠牲にします。rank-one 編集は 1.000 / 0.976 を 4% のパープレキシティで達成します。LoRA は表現力が高い代わりに制約がありません。[R9](RESULTS.md#r9-equal-budget-lora-baseline) を参照。

**70B モデルを編集できますか？**
Machaon の実測範囲は 8B までです。int8/int4 重みと局所的な密行列ウィンドウで求解を 10.2 GB 内に保ちます。それ以上はチェックポイントレベルで 1 tensor ずつストリームでき、評価パスは与えたメモリに応じてスケールします。求解コストは編集点以降のウィンドウで決まり、モデル全体ではありません。

**rank-one 編集で十分ですか？**
1 つの事実にはたいてい十分です。振る舞いには低ランク＋方向（`bake_direction` または `ablate_output`）が通常良いです。大量編集の次は MEMIT 風バッチ求解で、[ロードマップ](roadmap.md)にあります。今日は 1 つの `EditBudget` の下で事実ごとの編集を組み合わせるか、低ランク方向を使ってください。

**編集は成功したのに言い換えが失敗するのはなぜ？**
key が 1 つの token 列に縛られています。複数の言い換えから key を取り平均してください。言い換え集合も base model がもともと正しく答えるものにしてください。そうでなければノイズを測っています。

**`rank1_constrained` が "preserved subspace" を出すのはなぜ？**
target key が保護 key の張る空間に入り、2 つの制約が両立しません。保護集合を小さくするか、別の key を選んでください。

**なぜ平均ではなく `kl_p95` を報告するのですか？**
壊れた 1 つの prompt は、無傷の 100 個より重要です。平均はそれを隠します。

**なぜ間違いを直すのではなく target injection なのですか？**
Qwen2.5-0.5B は zsRE の最初の token を 300 個中 299 個正解するからです。モデルが間違える項目だけを編集するプロトコルは、強いモデルでは改善余地がほとんどありません。injection は弱いモデルでも強いモデルでも機能します。

**なぜ bf16 ではなく float32 ですか？**
CPU では PyTorch の bf16 backward が病的に遅い：同じ 0.5B モデルで 4.66 秒/step 対 float32 の 0.18 秒/step。delta はどちらも float64 で計算し、モデル dtype は value 求解の forward/backward にだけ影響します。

**層の選択がなぜそんなに重要ですか？**
層 12 の編集は後ろ 12 ブロックを通過します。Qwen2.5-0.5B では同じ編集が層 12 で rel. Δ 0.150、層 20 で 0.0043——35 倍の差です。

**Hugging Face にアクセスできません。**
`python scripts/fetch_model.py --repo ... --dest ...` を使うと ModelScope にフォールバックします。または `HF_ENDPOINT=https://hf-mirror.com` を設定してください。スクリプトは転送後に safetensors ヘッダーも検証します。

**なぜ反復率を baseline 相対で報告するのですか？**
GPT-2 は編集前から greedy decoding でループするからです。絶対しきい値は未編集モデルも失敗させ、編集について何も教えません。

**編集は何回重ねられますか？**
測ってください。GPT-2 では 32 回の rank-one 編集（累積 Δ 0.255）が 19% のパープレキシティ、8 回が 5%。`EditBudget(max_total=0.10)` はおよそ 10 回目で拒否し、推奨既定値です。

**指標が欠けると gate が失敗するのはなぜ？**
そうでなければ合格する最短経路は測定をやめることです。フェイルクローズは設計判断で、見落としではありません。

**OpenWSP を使わずにフォーマットだけ使えますか？**
はい。`machaon.interop.openwsp` は独立実装で、参照実装が生成した fixture に対する適合性テスト済みです。

**これは安全アラインメントを外しますか？**
方向アブレーションは 1 行でできます。だからプロジェクトは拒否ルール、追記専用編集記録、ゲートスイートを同梱しています。[SECURITY.md](https://github.com/S0ra-ai/Machaon/blob/main/SECURITY.md) を参照。
