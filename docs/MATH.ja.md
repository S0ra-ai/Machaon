# 数学的原理と失敗の仕方

## 1. Rank-one 編集（ROME）

重み `W ∈ R^{d_out × d_in}` が `W′ k = v` を満たし、できるだけ小さく変わることを望みます。この単一線形制約の最小 Frobenius ノルム解は rank one です：

```
ΔW = (v − W k) kᵀ / (kᵀ k)
```

確認：`ΔW k = (v − Wk)(kᵀk)/(kᵀk) = v − Wk`、したがって `W′ k = v`。∎

key には厳密ですが、他の入力について**何も**言いません。これが素朴な ROME 編集が近傍を壊す理由です。

## 2. 零空間制約編集

`K = [k₁ … kₙ]ᵀ` を変えたくない key、`Q` を `span(K)` の正規直交基底（`K` の SVD から）とします。定義：

```
P  = I − Q Qᵀ
k⊥ = P k
```

`k⊥` はすべての保護 key と直交します。これを書き込み方向に使います：

```
ΔW = (v − W k) k⊥ᵀ / (k⊥ᵀ k)
```

2 つの性質：

* **ターゲット** —— `ΔW k = (v − Wk)(k⊥ᵀk)/(k⊥ᵀk) = v − Wk`、つまり `W′ k = v`。厳密。
* **保護** —— 各 `i` について `ΔW kᵢ = (v − Wk)(k⊥ᵀ kᵢ)/(k⊥ᵀk) = 0`。厳密。

分子は**元の** `k` を使い、`k⊥` ではありません。両方に `k⊥` を使うのはよくあるバグで、値は入りますが余計なノルムを使います。

実装詳細：`d_in × d_in` 射影行列を実体化しません。基底形式は適用が `O(d_in · r)` で、`d_in = 4096` では密行列が層あたり 128 MB になります。

## 3. 方向アブレーション

モジュール出力の単位方向 `d` 成分を除くには：

```
W′ = (I − d dᵀ) W
```

residual stream に書き込むすべての行列に適用すれば、データなしで振る舞い（拒否方向、スタイル方向）を除けます。1 行、ゼロ勾配。この能力は dual-use でもあります——下の安全制御を参照。

## 4. 方向注入

推論時 steering は hidden state に `α d` を足します。residual stream は加法的なので、そこに書き込むモジュールに rank-one 項を足すのと等価です：

```
ΔW = α d aᵀ / (aᵀ a)
```

`a` は代表的な入力活性化。すると `W′ a = W a + α d`——steering ベクトルが重みに焼き込まれ、実行時 hook が不要になります。

## 5. 予算

```
rel(ΔW) = ‖ΔW‖_F / ‖W‖_F
```

層をまたいで一般化する唯一の安全ダイヤルです。`max_rel_norm` へのクリップは delta を縮め、**厳密な target 保証を壊します**——意図的に。クリップされた編集は、許可以上にモデルを使わず、少なめに届けます。

経験的な出発点：

| 編集タイプ | 予算 |
|---|---|
| 事実型、`down_proj` | 0.01 – 0.03 |
| 行動型、`o_proj` | 0.05 – 0.15 |
| ablation | クリップしない。KL を測る |

## 診断と回復

| 症状 | 原因 | 対処 |
|---|---|---|
| 正確な prompt は動くが言い換えが失敗 | key が 1 つの token 列に縛られている | 5–20 の言い換えで平均 |
| 短答は正しいが長文が崩れる | 編集が下流計算を壊した | 浅い層、低予算、強い投影 |
| 能力が落ちる | 層が中央すぎる | 2–4 層浅く |
| 無関係な prompt がドリフト | 零空間制約がない | 保護 key 集合を追加 |
| bf16 で何も変わらない | delta が丸めで消える | float64 で計算し後で戻す |
| 累積編集でモデルがドリフト | delta が蓄積 | `Σ‖ΔWᵢ‖/‖W‖` を ~0.1 に制限して再計算 |

## 適用範囲

この構成は、保護集合内のベクトルに対する正確な証明書と、編集した key における正確な目標達成を提供します。より広い局所性は、留出プローブ、中立 prompt、perplexity、タスク精度で測定します。この役割分担により、「契約が証明すること」と「評価が定量化すること」を明確に分けられます。低ランク・方向・複数編集の組み合わせで、より大きな関数変化へ同じパターンを拡張できます。

予算、保護集合の階数、ゲート群が適用範囲を明示するため、配備側はリスク許容度に合う動作点を選べます。

## 安全制御

方向アブレーションは 1 行で安全アラインメントを外せます。Machaon はそのため、宣言的意図、受入前拒否規則、追記専用監査記録、累積予算、fail-closed ゲート群を提供します。配備では監査ログを保持し、拒否行動を対象とする編集をレビューし、元チェックポイントを上書きせず新しいチェックポイントへ書き込んでください。
