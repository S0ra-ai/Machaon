# 数学原理与失效方式

## 1. Rank-one 编辑（ROME）

我们希望权重 `W ∈ R^{d_out × d_in}` 满足 `W′ k = v`，同时尽量少改。这个单线性约束的最小 Frobenius 范数解是 rank one：

```
ΔW = (v − W k) kᵀ / (kᵀ k)
```

验证：`ΔW k = (v − Wk)(kᵀk)/(kᵀk) = v − Wk`，因此 `W′ k = v`。∎

它对 key 精确，对任何其他输入**没有任何保证**。这就是朴素 ROME 编辑会损伤邻居的原因。

## 2. 零空间约束编辑

令 `K = [k₁ … kₙ]ᵀ` 是你拒绝改变的 key，`Q` 是 `span(K)` 的正交基（来自 `K` 的 SVD）。定义

```
P  = I − Q Qᵀ
k⊥ = P k
```

`k⊥` 与每个受保护 key 正交。用它作为写入方向：

```
ΔW = (v − W k) k⊥ᵀ / (k⊥ᵀ k)
```

两个性质：

* **目标** —— `ΔW k = (v − Wk)(k⊥ᵀk)/(k⊥ᵀk) = v − Wk`，因此 `W′ k = v`。精确。
* **保护** —— 对每个 `i`，`ΔW kᵢ = (v − Wk)(k⊥ᵀ kᵢ)/(k⊥ᵀk) = 0`。精确。

注意分子使用**原始** `k`，不是 `k⊥`。两边都用 `k⊥` 是常见 bug：它能把值打进去，但会多花不必要的范数。

实现细节：我们从不显式构造 `d_in × d_in` 投影矩阵。基形式应用成本是 `O(d_in · r)`；当 `d_in = 4096` 时，稠密投影每层要 128 MB。

## 3. 方向消融

要移除模块输出沿单位方向 `d` 的分量：

```
W′ = (I − d dᵀ) W
```

作用到每个写入 residual stream 的矩阵，就能不借助任何数据移除一种行为（拒绝方向、风格方向）。一行，零梯度。这也是这个能力危险的原因——见下面的安全说明。

## 4. 方向注入

推理时 steering 会给 hidden state 加 `α d`。由于 residual stream 是加性的，这等价于给写入该处的模块加一个 rank-one 项：

```
ΔW = α d aᵀ / (aᵀ a)
```

其中 `a` 是代表性输入激活。于是 `W′ a = W a + α d`——steering 向量被烘进权重，不再需要运行时 hook。

## 5. 预算

```
rel(ΔW) = ‖ΔW‖_F / ‖W‖_F
```

这是唯一能跨层通用的安全旋钮。裁剪到 `max_rel_norm` 会缩小 delta，**打破精确 target 保证**——这是刻意的。被裁剪的编辑会少交付，而不是比你授权的更多地消耗模型。

经验起点：

| 编辑类型 | 预算 |
|---|---|
| 事实型，`down_proj` | 0.01 – 0.03 |
| 行为型，`o_proj` | 0.05 – 0.15 |
| ablation | 不裁剪；改测 KL |

## 失效方式

| 症状 | 原因 | 修复 |
|---|---|---|
| 精确 prompt 有效，改写失败 | key 绑定单一 token 序列 | 对 5–20 个改写取平均 |
| 短答正确，长文本不连贯 | 编辑破坏了下游计算 | 更浅的层、更低预算、更强投影 |
| 能力下降 | 层太居中 | 往浅层移动 2–4 层 |
| 无关 prompt 漂移 | 没有零空间约束 | 加受保护 key 集 |
| bf16 下什么都没变 | delta 被舍入吃掉 | 用 float64 计算，之后再合并 |
| 累计编辑让模型崩溃 | delta 累积 | 把 `Σ‖ΔWᵢ‖/‖W‖` 限制在 ~0.1，然后重新计算 |

## 保证的边界

以上一切都是**一阶且局部的**。`ΔW kᵢ = 0` 对你受保护集合中的精确向量成立；邻近输入只被近似保留。下游非线性会放大微小误差。更复杂的函数变化由低秩、方向或多编辑组合承担。

把这些公式看成一把握持宽度已知的手术刀，而不是“其他东西一定没动”的证明。验收门就是为此存在的。

## 安全

方向消融可以一行移除安全对齐。任何部署都应保留每次编辑的追加式审计日志，拒绝意图移除拒绝行为的编辑，并且从不原地覆盖检查点。
