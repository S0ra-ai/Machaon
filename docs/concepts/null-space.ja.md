# 零空間投影

これはプロジェクトの土台となる一つのアイデアです。

## 問題

key `k` を value `v` に写す rank-one 編集は、単一制約の最小ノルム解です：

```
ΔW = (v − W k) kᵀ / (kᵀ k)
```

`k` には厳密ですが、他の入力については何も言いません。実際には隣接 key を動かし、損傷を与えます。

## 修正

`K = [k₁ … kₙ]ᵀ` を変えたくない key、`Q` を `span(K)` の正規直交基底とします。射影 `P = I − Q Qᵀ` を定義し、射影した key に沿って編集を書きます：

```
k⊥  = P k
ΔW  = (v − W k) k⊥ᵀ / (k⊥ᵀ k)
```

すると：

- **ターゲット**：`ΔW k = v − W k`、つまり `W' k = v`。厳密。
- **保護**：すべての保護 key について `ΔW kᵢ = 0`。機械精度で厳密。

分子は**元の** `k` を使うことに注意。両方で `k⊥` を使うのはよくあるバグで、値は入りますが余計なノルムを使います。

## 実装メモ

ホットパスで `d_in × d_in` 射影行列を実体化しません：

```python
Q = nullspace_basis(preserve)          # (d_in, r)
k_perp = project_complement(k, Q)      # k - Q Qᵀ k, O(d_in · r)
```

`d_in = 4096`、`r = 32` なら、128 MB の密行列ではなく 0.5 MB の基底で済みます。

## 失敗するとき

**ターゲット key が保護部分空間に入る。** このとき `k⊥ ≈ 0` で、両方の制約を満たす編集は存在しません。Machaon は黙って劣化せず、エラーを出します：

```
ValueError: target key lies in the preserved subspace: the edit cannot be made
without changing protected behaviour
```

これはバグではなくシグナルです：保護集合を小さくするか、別の key を選びます。

## 保証の範囲

保証は**一次で、保護集合上では厳密**です：与えたベクトルに対して `ΔW kᵢ = 0` が機械精度で成り立ちます。近傍入力は一次近似で保たれ、残りは事後チェックで測ります：key には [`verify`](../reference/api.md)、無関係な prompt には KL。

刃幅が既知のメスとして扱ってください。「他は何も動いていない」という証明ではありません。
