# Machaon の位置づけ

仕事によって道具は変わります。このページは短い地図です：各手法が何を変え、何を戻せて、局所性の証拠をどこから取り、Machaon がどこに契約を足すか。

| 手法 | 変更単位 | 取り消し | 局所性の証拠 | 最適な用途 |
|---|---|---|---|---|
| **Machaon** | 内容アドレス指定の 1 つの delta | ビット単位ロールバック | 保護 key ドリフト + KL + ゲート | 監査可能な単発編集、agent ワークフロー |
| ファインチューニング | 全重み、勾配経由 | チェックポイント復元 | ベンチマーク | 広い能力・スタイル変更 |
| LoRA / PEFT | adapter 重み | adapter を外す | ベンチマーク | パラメータ効率の良い適応 |
| ROME / MEMIT | rank-one またはバッチ delta | 既定ではなし | 論文固有のプローブ | 事実編集の研究 |
| 活性化 steering | 実行時 hook | hook を外す | プローブ prompt | 推論時制御 |
| mergekit / task arithmetic | モデル全体のマージ | 両親を保持 | マージ評価 | 学習済みモデルの合成 |
| 剪枝 / 再配線 | 構造 | 元チェックポイントを保持 | ベンチマーク | サイズ・遅延削減 |

Machaon は意図的に狭く、**標的編集**とその周りの**受け入れ契約**を担当します。他の行は 1 呼び出し先にあり、成果物は同じ監査に入れられます：

- mergekit や task-arithmetic の delta は `machaon.verify` で検査し、`machaon.tools.apply_delta` で適用できます；
- 他ツールの OpenWSP 編集は読み取り、ハッシュ検証、ゲートができます；
- LoRA adapter は同じステップ数・同じ層の比較 baseline になります（[R9](RESULTS.md#r9-equal-budget-lora-baseline)）；
- steering 方向は `bake_direction` で重みに焼き込み、他の delta と同様に監査できます。

## Machaon がパラメータ編集に足すもの

1. **宣言された制約。** 保護 key は編集の一部で、後付けの願望ではありません。
2. **予算。** `Σ‖ΔWᵢ‖/‖W‖` は commit 時に課金され、超過を拒否します。
3. **トランザクション。** すべての編集はバイト単位で戻せます。
4. **判定。** 8 つのフェイルクローズゲート。欠損指標は失敗。
5. **可搬な記録。** OpenWSP v1、バイト一致、インポート時にハッシュ検証。
6. **agent 表面。** 12 の MCP ツール。ファイルレベルとモデルレベル。

## 一行で選ぶ

- 1 つの事実や行動を変え、証拠が必要：**Machaon**。
- モデル全体のスタイルや能力を変える：**ファインチューニング**。
- 小さな学習可能 adapter を足す：**LoRA**。
- 2 つの学習済みモデルを合成する：**mergekit**。
- 重みを書かず推論時に steer する：**活性化 steering**。
