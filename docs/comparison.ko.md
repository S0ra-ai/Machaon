# Machaon의 위치

작업마다 도구가 다릅니다. 이 페이지는 짧은 지도입니다: 각 접근이 무엇을 바꾸고, 무엇을 되돌릴 수 있고, 국소성 증거를 어디서 얻고, Machaon이 어디에 계약을 더하는지.

| 접근 | 변경 단위 | 되돌리기 | 국소성 증거 | 최적 용도 |
|---|---|---|---|---|
| **Machaon** | 내용 주소 기반의 단일 delta | 비트 단위 롤백 | 보호 key 드리프트 + KL + 게이트 | 감사 가능한 단일 편집, agent 워크플로 |
| 파인튜닝 | 전체 가중치, 그래디언트 | 체크포인트 복원 | 벤치마크 | 넓은 능력·스타일 변경 |
| LoRA / PEFT | adapter 가중치 | adapter 제거 | 벤치마크 | 파라미터 효율 적응 |
| ROME / MEMIT | rank-one 또는 배치 delta | 기본적으로 없음 | 논문별 프로브 | 사실 편집 연구 |
| 활성화 steering | 런타임 hook | hook 제거 | 프로브 prompt | 추론 시 제어 |
| mergekit / task arithmetic | 모델 전체 병합 | 두 부모 보존 | 병합 평가 | 학습된 모델 결합 |
| 프루닝 / 재배선 | 구조 | 원본 체크포인트 보존 | 벤치마크 | 크기·지연 감소 |

Machaon은 의도적으로 좁게, **표적 편집**과 그 주변의 **수용 계약**을 담당합니다. 다른 행은 한 번의 호출 거리에 있고, 산출물은 같은 감사에 들어갈 수 있습니다:

- mergekit 또는 task-arithmetic delta는 `machaon.verify`로 검사하고 `machaon.tools.apply_delta`로 적용할 수 있습니다;
- 다른 도구의 OpenWSP 편집은 읽고, 해시를 검증하고, 게이트할 수 있습니다;
- LoRA adapter는 같은 스텝 수, 같은 레이어의 비교 baseline이 됩니다([R9](RESULTS.md#r9-equal-budget-lora-baseline));
- steering 방향은 `bake_direction`으로 가중치에 구워 다른 delta처럼 감사할 수 있습니다.

## Machaon이 파라미터 편집에 더하는 것

1. **선언된 제약.** 보호 key는 편집의 일부이며 사후 희망이 아닙니다.
2. **예산.** `Σ‖ΔWᵢ‖/‖W‖`는 commit 시 청구되고 초과를 거부합니다.
3. **트랜잭션.** 모든 편집은 바이트 단위로 되돌릴 수 있습니다.
4. **판정.** 8개의 페일 클로즈 게이트. 누락 지표는 실패.
5. **이식 가능한 기록.** OpenWSP v1, 바이트 일치, 가져올 때 해시 검증.
6. **agent 표면.** 12개의 MCP 도구. 파일 수준과 모델 수준.

## 한 줄 선택

- 하나의 사실이나 행동을 바꾸고 증거가 필요: **Machaon**.
- 모델 전체의 스타일이나 능력을 바꿈: **파인튜닝**.
- 작은 학습 가능 adapter 추가: **LoRA**.
- 두 학습된 모델 결합: **mergekit**.
- 가중치를 쓰지 않고 추론 시 steer: **활성화 steering**.
